# Отчёт по этапу 5 «Инспекция кода модулей проекта»

## 1. Цель работы
Провести формализованную проверку исходного кода системы управления задачами, выявить архитектурные и логические недочеты, а также подтвердить результаты инструментальными проверками.

## 2. Исходное состояние
- **Ветка:** `feature/stage-5-code-inspection` (создана от `main`).
- **Инструменты:** .NET 10, Git, xUnit.

## 3. Таблица замечаний
| № | Место | Проблема | Риск | Рекомендация | Статус |
|---|-------|----------|------|--------------|--------|
| 1 | `tests/TaskManagement.UnitTests/UserServiceTests.cs`, `TaskServiceTests.cs` | Несоответствие символов переноса строк (ENDOFLINE) и отсутствие пустых строк в конце файлов. | Сложности при командной разработке на разных ОС, шум в Git-диффах. | Применить автоформатирование согласно правилам `.editorconfig`. | Исправлено |
| 2 | `tests/TaskManagement.UnitTests/TaskServiceTests.cs` | Предупреждение компилятора `CS8625` (передача `null` в ненулевой параметр). | Потенциальный риск скрытия реальных ошибок nullability в тестах. | Использовать оператор `!` (null-forgiving) для явного указания намерения передать `null` в тесте. | Исправлено |
| 3 | `src/TaskManagement.Tasks/TaskService.cs` | В методе `CreateTaskAsync` отсутствует проверка на пустой `ProjectId`. | Создание задач, не привязанных к проектам, нарушение целостности данных. | Добавить проверку `if (projectId == Guid.Empty) return false;`. | Исправлено (на этапе 4) |

## 4. Инструментальная проверка
В ходе инспекции выполнены следующие команды:
- `dotnet format --verify-no-changes` — код полностью соответствует правилам `.editorconfig` (после внесения исправлений).
- `dotnet build` — сборка успешна, **0 предупреждений, 0 ошибок**.
- `dotnet test` — все **6 тестов** пройдены успешно.

## 5. Внесенные исправления
В рамках этапа были устранены замечания форматирования (автоматически через `dotnet format`), а также исправлено предупреждение компилятора в тестах (путем добавления оператора `null!`).

Инспекция кода показала, что проект имеет четкую архитектуру с разделением на модули и контракты. Инструментальные проверки подтвердили отсутствие ошибок сборки и успешное прохождение всех тестов. Выявленные замечания по форматированию и предупреждениям компилятора устранены.
